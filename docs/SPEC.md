# Queue Master — специфікація бота

Telegram-бот для черги на здачу лаб у груповому чаті. Google Sheets і зовнішні API не потрібні: список живе в боті, а «таблиця» — це закріплене повідомлення в групі, яке бот редагує.

## 1. Основна ідея

- Староста створює чергу. Часу в ній немає, тільки порядок: номер, ім'я, ✅.
- Студенти записуються самі, кнопкою або командою.
- Бот тегає того, чия черга, і попереджає наступного.
- Студент натискає «✅ Готово» — бот ставить ✅ і кличе наступного.

Бонус: студенти записуються зі свого акаунта, тож бот одразу знає їхній `user_id` і може тегати будь-кого, навіть без @username. Окремо прив'язувати імена не потрібно.

## 2. Вигляд закріпленого повідомлення

```
📋 Лаба 3 — ООП
🟢 Приймають · здали 2 з 6

1. ✅ Коваленко Олена
2. ✅ Бондар Марта
3. ▶️ Шевчук Тарас  ← здає
4. ⏳ Ткаченко Андрій ↩️  ← готується
── ☕ перерва ──
5. ▫️ Мельник Ірина
6. ▫️ Кравець Софія

[✋ Записатися] [📍 Де я?]
[🏃 Йду]        [✅ Готово]
[⏬ Пізніше]    [🚪 Заходжу]
[❌ Виписатися]
```

Бот редагує одне це повідомлення, а не шле нові. Нове повідомлення з'являється тільки разом із тегом «твоя черга», і попереднє таке бот видаляє, тож у чаті завжди лише одне актуальне.

↩️ означає, що людина повернулася після пропуску.

## 3. Команди і кнопки

### Для всіх

| Кнопка / команда | Що робить |
|---|---|
| **✋ Записатися** | ставить у кінець черги; якщо тебе пропустили — повертає в чергу (як «Я тут») |
| **📍 Де я?** | спливаюче вікно лише тобі: скільки людей попереду й орієнтовний час |
| **🏃 Йду** | тебе покликали, ти йдеш (інакше автопропуск) |
| **✅ Готово** / `/done` / відповідь «Закінчив» на повідомлення бота | здано, бот кличе наступного |
| **🚪 Заходжу** / `/enter` | для наступного в черзі: попередній вийшов або не прийшов, а ти заходиш (див. розділ 4) |
| **⏬ Пізніше** / `/later` | помінятися місцями з наступним у черзі |
| **🙋 Я тут** / `/here` | пропущений повертається в чергу (зі штрафом, див. розділ 4) |
| **❌ Виписатися** / `/leave` | вийти з черги; кнопка спрацьовує з другого натискання протягом 5 с |
| `/name Прізвище Ім'я` | як показувати тебе в черзі (за замовчуванням — ім'я з Telegram) |
| `/help` | усі команди |

- Кнопки відповідають спливаючим вікном, яке бачить лише той, хто натиснув.
- Успішні команди бот підтверджує реакцією 👍.
- На помилку в команді бот відповідає в чаті, і ця відповідь зникає через 15 с (довгі підказки — через 90 с).

«✅ Готово» приймається тільки від того, хто **зараз здає**, або від адміна. Як «Закінчив» у відповідь на повідомлення бота рахуються (без урахування регістру): `закінчив`, `закінчила`, `готово`, `все`, `здав`, `здала`, `здано`, `done`.

### Для адмінів групи

| Команда | Що робить |
|---|---|
| `/new Лаба 3 перерва кожні 5 чекати 3` | створює чергу; перерва й очікування необов'язкові |
| `/go` | запускає чергу і тегає першого; під час перерви закінчує її |
| `/skip` | поточний не прийшов: пропуск зі штрафом, бот кличе наступного |
| `/wait 5` | скільки хвилин чекати на «🏃 Йду» (0 — без автопропуску) |
| `/breaks 5` | перерва після кожних 5 здач (0 — без перерв) |
| `/done 3` | відмічає номер 3 як здачу (викладач прийняв когось поза чергою) |
| `/repost` | надсилає повідомлення черги заново вниз чату і закріплює |
| `/add Прізвище Ім'я` | дописує в кінець людину без Telegram (без тегу) |
| `/remove 3` | прибирає номер 3 |
| `/close` | закриває чергу, відкріплює повідомлення |

Адмін — це адміністратор Telegram-групи (перевіряється через `getChatAdministrators`).

## 4. Логіка черги

Кожна людина має статус: `waiting` → `current` → `done` або `skipped`.

- **Порядок виклику** — це порядок у списку. Нові люди стають у кінець (до 50 людей).
- **Наступний** = перший у списку зі статусом `waiting`. Він же отримує «готуйся».
- Записатися можна й після `/go`. Якщо чекати нікому, нового кличуть одразу.

### Перерви

- Після кожних N здач бот оголошує перерву і **нікого не кличе**.
- Перерва триває, доки наступна людина або адмін не натисне «✅ Готово» (або `/done`, «🚪 Заходжу»; адмін — ще `/go`).
- Рахуються здачі поточних людей; пропущені не рахуються. Якщо далі нікого немає, перерви не буде.
- Якщо наступний уже зайшов («🚪 Заходжу»), перерва буде після нього.

### Неявки

1. Людина має натиснути **🏃 Йду** протягом `wait_minutes` (за замовчуванням 3 хв).
2. Не натиснула — **автопропуск**, бот кличе наступного.
3. Пропущений натискає **🙋 Я тут** (або ✋, або `/here`) і повертається зі штрафом: після 1-го пропуску вперед іде 1 людина, після 2-го — 2, далі — в кінець.
4. Людей без Telegram (`/add`) автопропуск не чіпає.
5. Після перезапуску бота таймери відновлюються, але з мінімум хвилиною запасу.

### «🚪 Заходжу» — коли попередній забув або не прийшов

Натиснути може наступний у черзі (через 60 с після виклику поточного) або адмін:

| Попередній… | Що буде з ним |
|---|---|
| натискав «Йду» (або він без Telegram) | забув «Готово» → ✅ ставиться автоматично |
| не натискав | не прийшов → ⏭ пропуск зі штрафом |

Якщо ✅ поставили помилково, людина натискає **🙋 Я тут** і стає наступною без штрафу.

### Нагадування

- Коли людина натискає «🏃 Йду», бот у спливаючому вікні нагадує натиснути «✅ Готово», як вийде.
- Якщо здача триває **удвічі довше за середню** (рахується за останніми 5 людьми, але не менше 10 хв), бот один раз пише: «⏰ @X, ти ще в кабінеті? Якщо вже все — натисни «✅ Готово»». У цьому ж повідомленні він підказує наступному, що можна натиснути «🚪 Заходжу».

## 5. Технічні рішення

- **Privacy mode залишається увімкненим.** Бот бачить тільки команди й відповіді на свої повідомлення. Цього достатньо, читати весь чат не треба.
- **Топіки (forum):** черга прив'язана до `chat_id + message_thread_id`, бот пише в той топік, де її створили.
- **Одна активна черга на чат/топік.** Два викладачі одночасно — це дві черги в різних топіках.
- **Ліміти Telegram** (~20 повідомлень/хв у групі): закріплене повідомлення редагується не частіше разу на секунду, помилка `message is not modified` ігнорується.
- **Свої повідомлення бот видаляє без прав адміна.** Так він прибирає старі «твоя черга» і відповіді-помилки.

## 6. Стек

- Python 3.12+
- aiogram 3 (long polling)
- SQLite через aiosqlite

## 7. Модель даних

```
queues
  id, chat_id, thread_id, title, wait_minutes,
  break_every, turns (здач після перерви), on_break,
  message_id, status (open | running | closed), created_by, created_at

slots
  queue_id, position (порядок виклику), user_id, name,
  status (waiting | current | done | skipped),
  skips, called_at, confirmed, done_at, nudged, auto_done

users
  user_id, name (з команди /name)
```

- Чи потрібна «пам'ять» між парами (хто не встиг — першим наступного разу)? Поки що ні.
