# Queue Master — специфікація бота

Telegram-бот для черги на здачу лаб у груповому чаті. Без Google Sheets і зовнішніх API: список живе в боті, а «таблиця» — це закріплене повідомлення в групі, яке бот редагує.

## 1. Основна ідея

- Староста створює чергу з часовими слотами (як у звичній таблиці: час | ім'я | ✅).
- Студенти записуються самі — кнопкою або командою.
- Бот тегає того, чия черга, і попереджає наступного.
- Студент каже «Закінчив» — бот ставить ✅ і кличе наступного.

Бонус: оскільки студенти записуються зі свого акаунта, бот одразу знає їхній `user_id`, тож тегати можна будь-кого, навіть без @username. Окрема прив'язка імен не потрібна.

## 2. Вигляд закріпленого повідомлення

```
📋 Лаба 3 — ООП

10:25  ✅ Муха Аскольд
10:30  ✅ Петрашкевич Артем
10:35  ▶️ Соболь Єгор          ← здає
10:40  ⏳ Іщук Євгеній         ← готується
10:45  ·  Мельничук Михайло
10:50  ·  —
10:55  ·  Мазурець Софія
── перерва ──
12:20  ·  Гапєєв Тимофій
12:25  ⏭ Борисова Олеся        (пропущена)

[✋ Записатися] [🚪 Виписатися]
[✅ Я закінчив] [⏬ Пізніше]
```

Бот редагує одне це повідомлення, а не шле нові. Нові повідомлення — тільки для тегів «твоя черга».

## 3. Команди

### Для всіх

| Команда / дія | Що робить |
|---|---|
| кнопка **✋ Записатися** | займає перший вільний слот |
| `/join 10:45` | займає конкретний слот (якщо вільний) |
| кнопка **🚪 Виписатися** / `/leave` | звільняє свій слот |
| кнопка **✅ Я закінчив** / `/done` / відповідь на повідомлення бота «Закінчив» | позначає здачу, бот кличе наступного |
| кнопка **⏬ Пізніше** / `/later` | міняється місцями з наступним у черзі |
| `/here` | пропущений студент повертається — стає наступним після поточного |
| `/name Прізвище Ім'я` | як показувати тебе в черзі (за замовчуванням — ім'я з Telegram) |
| `/help` | усі команди |

Успішні команди бот підтверджує реакцією 👍 на повідомлення (щоб не засмічувати чат), помилки — відповіддю з поясненням.

`/done` і «Закінчив» приймаються тільки від **поточного** студента або адміна.

Слова, які рахуються як «Закінчив» (у відповідь на повідомлення бота, без урахування регістру): `закінчив`, `закінчила`, `готово`, `все`, `done`.

### Для адмінів групи

| Команда | Що робить |
|---|---|
| `/new Лаба 3 10:25-13:00 5 перерва 12:00-12:20` | створює чергу: назва, проміжок, крок у хвилинах, перерви (необов'язково, можна кілька). Кінець проміжків **не включно**: `10:25-13:00` → останній слот 12:55 |
| `/go` | запускає чергу — тегає першого |
| `/skip` | поточний не прийшов → статус «пропущений», кличе наступного |
| `/done 10:45` | відмічає конкретний слот як здачу (викладач прийняв когось поза чергою) |
| `/repost` | надсилає повідомлення черги заново вниз чату і закріплює |
| `/add 10:45 Прізвище Ім'я` | вписує людину без Telegram (буде без тегу) |
| `/remove 10:45` | звільняє слот |
| `/close` | закриває чергу, відкріплює повідомлення |

Адмін = адміністратор Telegram-групи (перевіряється через `getChatMember`).

## 4. Логіка черги

Кожен слот має статус: `empty` → `waiting` → `current` → `done`, або `skipped`.

- **Наступний** = перший за часом слот зі статусом `waiting`.
- **Готується** = другий такий слот (отримує попередження).
- Порожні слоти просто пропускаються.
- Записатися можна і після `/go`, але тільки в слот **після** поточного — у минулі слоти не можна, щоб не перестрибувати чергу. Якщо всі вже здали, новий записаний одразу стає поточним.
- `/skip` → поточний стає `skipped`; `/here` від нього → повертається в `waiting` одразу після поточного.
- Коли `waiting` більше немає — бот пише «Черга закінчилась 🎉».

## 5. Технічні рішення

- **Privacy mode залишається увімкненим.** Бот бачить тільки команди й відповіді на свої повідомлення — цього достатньо, читати весь чат не треба.
- **Топіки (forum):** черга прив'язана до `chat_id + message_thread_id`, бот пише в той топік, де її створили.
- **Одна активна черга на чат/топік.** Два викладачі одночасно = дві черги в різних топіках.
- **Ліміти Telegram** (~20 повідомлень/хв у групі): редагування закріпленого повідомлення з дебаунсом ~1 с; помилку `message is not modified` ігнорувати.

## 6. Стек

- Python 3.12
- aiogram 3 (long polling)
- SQLite через aiosqlite

## 7. Модель даних

```
queues
  id, chat_id, thread_id, title, message_id (закріплене),
  status (open | running | closed), created_by, created_at

slots
  id, queue_id, time ("10:25"), position (порядок),
  user_id (nullable), display_name (nullable),
  status (empty | waiting | current | done | skipped)

users
  user_id, name (з команди /name)
```
